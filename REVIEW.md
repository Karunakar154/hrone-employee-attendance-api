# REVIEW.md

The findings below are defects in the original starter `app/main.py`, before the implementation was expanded. The locations refer to function names because line numbers change as the file is edited.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | It builds the shift start by replacing the punch-in's clock fields. This uses the punch-in's timezone/date rather than the employee's IST attendance date and does not correctly handle overnight shifts. | Test a UTC instant that converts to a different IST date, and test an overnight shift. Late minutes can be wrong. | Convert instants consistently to IST, derive the attendance date using R1, and calculate against the shift-start instant for that attendance date. |
| 2 | `compute_late_minutes` | The grace-period comparison and whole-minute calculation need the contract's strict `> 10 minutes` rule and second-level truncation. | For a 09:30 shift, 09:40:00 must be 0 and 09:40:01 must be 10. | Truncate instants to whole seconds and apply the strict threshold before returning whole elapsed minutes. |
| 3 | `compute_work_hours` | Built-in `round()` uses ties-to-even for exact halfway cases; the contract requires decimal half-up rounding. | Test a duration whose hour value lands on a half-cent boundary. | Use `Decimal` with `ROUND_HALF_UP` for the required two-decimal result. |
| 4 | `compute_overtime` | It creates a timezone-aware shift-end datetime but the starter punch timestamps can be naive, causing aware/naive subtraction errors. It also assumes shift end is on the attendance date, which is wrong for overnight shifts. | Punch out after midnight for a 22:00–06:00 shift; the result can be wrong or raise `TypeError`. | Normalize instants consistently and place the shift end on the next calendar day when the shift is overnight. Apply the 30-minute minimum and floor whole minutes. |
| 5 | `GET /health` (`health`) | It always returns `{"status":"ok"}` without checking MongoDB readiness. | Stop MongoDB and call `/health`; the starter still returns success. | Run a MongoDB ping and return 503 if the database is unavailable. |
| 6 | `POST /employees` (`create_employee`) | Checking for a duplicate before inserting is a check-then-insert race; two simultaneous requests can both pass the check. | Send parallel create requests with the same `emp_code`. More than one request may pass the pre-check. | Create a unique index on `employees.emp_code` at startup and translate `DuplicateKeyError` to 409. |
| 7 | `GET /employees` (`list_employees`) | `skip = page * page_size` skips the first page, and `total` counts all employees rather than the filtered query. Results are not sorted by `emp_code`; pagination values are not constrained. | With page 1 and page size 20, the first 20 records are skipped; filtering by department gives an incorrect total. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and validate page/page_size according to R10. |
| 8 | `POST /attendance/punch-in` (`punch_in`) | An unknown employee makes `emp` be `None`, then `emp["shift_start"]` fails instead of returning 404. | Punch in using an unknown `emp_code`; the starter can return 500. | Check that the employee exists and return 404 before reading employee fields. |
| 9 | `POST /attendance/punch-in` (`punch_in`) | `datetime.fromtimestamp()` uses the machine's local timezone, and `if body.punched_at` treats zero as if the timestamp were omitted. Attendance date is also derived without explicitly applying IST rules. | Run under a different host timezone or submit an invalid/edge timestamp; the stored date may differ from R1. | Strictly validate epoch milliseconds, distinguish omitted values from supplied values, truncate to seconds, convert at the API boundary, and derive the attendance date in IST. |
| 10 | `POST /attendance/punch-in` (`punch_in`) | The duplicate lookup followed by `insert_one` is not race-safe; the starter has no unique (`emp_code`, `date`) index. | Send two simultaneous punch-ins for the same employee/day; both can pass the lookup. | Add a unique compound index on `attendance_logs (emp_code, date)` and map duplicate-key errors to 409. |
| 11 | `PunchInIn` model | `status` is a free-form string, so unsupported values are accepted. | Submit a status such as `"HOLIDAY"`; validation should reject it with 422. | Restrict status to `PRESENT`, `WFH`, or `ON_DUTY` for punch-in. Validate the other request fields and timestamp types too. |
| 12 | `GET /attendance` (`list_attendance`) | It fetches all matching records into Python, sorts and paginates in memory. This scales poorly at 100,000 records and risks high memory use. | Test with a large collection; response time and memory grow with the full result set even for a small page. | Use MongoDB filtering, indexed sort, `count_documents` for the filtered total, and database-side `skip`/`limit`. |
| 13 | `GET /attendance` (`list_attendance`) | The response exposes an `id` derived from MongoDB `_id`, although the data model says `_id` is internal and attendance records are addressed by (`emp_code`, `date`). | Compare the response to the OpenAPI schema and send a record request using the documented business key. | Serialize only the contract fields and omit `_id`/synthetic `id`. |
| 14 | Endpoints marked TODO | Punch-out, regularization, all four analytics endpoints, and the explain endpoint were not implemented in the starter. | Calling these contract paths returns 404 or they are absent from OpenAPI. | Implemented the required routes, with MongoDB aggregation pipelines for analytics and execution-stats explain output. |

## Reviewed and not considered defects

- The collection names `employees` and `attendance_logs` match `DATA_MODEL.md`.
- `emp_code`, not MongoDB `_id`, is the business identity; `_id` should remain internal.
- `date` and `joined_on` are strings by design, while punch instants are BSON datetimes. The fix should preserve these storage types rather than converting calendar dates into timestamps.
- Missing legacy `history` and `half_day` fields are allowed and should be treated as `[]` and `false`, respectively.
